# Daymark 事项保护

在 Obsidian 中隐藏并保护事项行末的完整 `^daymark-obsidian-UUID`。实时预览和源码模式都隐藏，编辑当前行时也不显示；原始 Markdown 仍保存 ID，Daymark 继续通过它关联时间记录。不更换已有 ID，不迁移数据格式。

## 安装

本工作区已构建好可安装目录：`release/daymark-id-guard/`。只需其中的 `main.js` 和 `manifest.json`，不需要复制源代码或 `node_modules`。

1. 将 `release/daymark-id-guard/` 整个文件夹复制到 Obsidian 仓库的 `.obsidian/plugins/`，得到 `.obsidian/plugins/daymark-id-guard/main.js` 和 `manifest.json`。
2. 在 Obsidian「设置 → 第三方插件」允许第三方插件，重新加载后启用「Daymark 事项保护」。插件为本地安装，无需上架社区目录。
3. 打开插件设置，填写**仓库内相对路径**并点击「保存并启用」。例如，仓库为 `D:\Vault`，Daymark 同步目录为 `D:\Vault\工作\Daymark`，这里填写 `工作/Daymark`。仓库根目录填写 `/`；留空表示关闭。只处理该目录直属的 `.md` 文件，与 Daymark 的导入范围一致。
4. 如果以前启用了 `obsidian-daymark.css` 或 `obsidian-daymark-reveal-on-edit.css`，请停用，避免它们继续影响其他块 ID 或遮住解锁后的 ID。

更新时停用插件，替换这两个安装文件，再启用。保留插件目录中的 `data.json` 即可保留目录设置；停用或卸载不会删除 Markdown 中的身份。

0.2.1 修复宿主先处理回车时旧 ID 被带到下一条空事项的问题。更新后必须关闭再开启插件，或重新启动 Obsidian，让编辑器加载新版代码；只覆盖磁盘上的 `main.js` 不会替换已运行的扩展。

## 编辑规则

| 操作 | 行为 |
| --- | --- |
| 修改名称、描述、结果、勾选状态、缩进 | 保留原 ID |
| 移动光标或按 End 到行末 | 跳过隐藏字段；普通输入在 ID 之前 |
| 局部删除、替换隐藏字段 | 在写入编辑器之前拦截；保留当前内容和选区 |
| 当前事项正文中按 Enter | 保留原事项身份，在现有子树之后另建带新 ID 的同级事项，子事项仍属于原父事项；从名称开头回车时原身份随原正文移到下一行 |
| 宿主快捷键先处理回车、直接插入单次换行或重写当前行 | 事务写入前识别安全分条并使用同样的身份规则，不只检查旧 ID 是否仍存在；关闭插件后源码仍保持对应 |
| 空事项按 Enter | 退出列表，移除该空事项及其 ID |
| 无选区 Ctrl+X / Ctrl+C | 剪切／复制整行，包括不可见的原 ID |
| 选中完整的可见事项行后剪切／复制 | 所有行原 ID 完整进入剪贴板，包括最后一条隐藏的行末 ID；只选择名称仍属于文字编辑 |
| 跨文件粘贴剪切或复制的完整事项 | 原样保留剪贴板中的 ID，不重新生成身份 |
| 重复粘贴、插件重启后粘贴、外部来源的 ID | 仍保留原 ID；Daymark 合并父事项及解析字段一致的条目，有差异时才报冲突 |
| 普通文字复制 | 不把选区中隐藏 ID 的片段输出到剪贴板 |
| 撤销／重做 | 使用 Obsidian 编辑器历史，恢复当次操作的原始 ID |

**移动多个事项不需要专用命令。** 使用一个连续选区，从第一条的行首（含缩进和列表符号）选到最后一条的可见行末，再按 Ctrl+X / Ctrl+V。最后一条不可见的 ID 会自动补入选区；中间各行的 ID 原本就在源码选区内。反向选择以及选到下一行行首也支持。目标文件应在配置目录中，使用插件处理粘贴。

0.2.0 已移除子树剪切、复制和删除命令。命令面板只保留 **显示并解锁 ID／恢复隐藏保护**：维护身份时临时显示并允许修改。解锁作用于配置目录，重新加载插件后自动恢复保护。

## 复制、搬移与重复 ID

0.2.0 起，Ctrl+C 与 Ctrl+X 都完整保留原 ID，粘贴不判断你是在搬移还是建立副本，也不自动更换身份。这样复制后删除原处也可以完成搬移，Daymark 中的时间记录继续引用同一身份。与 0.1.0 的“复制生成新 ID”行为不同。

**同一 ID 可以对应多个文档位置，Daymark 中仍是一个逻辑节点。** 比较父事项 ID、名称、描述、结果、状态、显式完成日期和自身标签；全部一致就合并，各处不同的子事项按 ID 汇总，可递归合并。位置、缩进和子事项列表可以不同，标签顺序和重复不影响比较。只有父事项或解析字段有差异才冲突，不采用先读到的内容覆盖。不同文件的顶层条目属于不同的文件父事项，正文相同但父 ID 不同仍会冲突，详见 [共享身份规则](../../docs/obsidian.md#稳定身份与单向同步)。

Daymark 的冲突详情会列出所有相关事项的名称、文件名、原始行号和差异字段的具体值；详情窗口可以滚动和复制，无需先解锁并搜索隐藏 ID。合并规则和冲突提示由 Daymark 桌面程序提供，更新桌面程序后生效，不需要更换插件。发生冲突时保留源文件和之前已保存的事项、时间记录。

- 想搬移：选中完整行，Ctrl+X / Ctrl+V；或 Ctrl+C / Ctrl+V 后删除原处，再同步。
- 想保留两个独立事项：复制后使用解锁命令，移除**副本**的行末 ID，恢复保护后同步，由 Daymark 为副本生成新 ID。
- 想在多处保留同一个事项：复制后保持父事项与解析字段一致，各处可以有不同的子事项；同步显示一个节点并汇总子事项，时间记录仍引用原 ID，不重复计算。
- 修改其中一个位置后，需要同步更新其他位置的解析字段，否则同步会指出冲突；Daymark 不自动回写副本。删除一个出现位置不等于删除整个逻辑事项，直到全部位置消失才按既有记录引用规则处理。

没有 ID 的新事项仍可正常输入，下一次 Daymark 同步会生成 ID。插件通过回车创建的事项直接获得新 ID。事项名称不能为空；未填完的空事项请填好或退出列表后再同步。

## 范围与限制

- 仅处理有效的 Daymark 事项行末身份；笔记 YAML 的 `daymark-id`、其他原生块 ID、代码块和注释不属于本插件的保护范围。格式错误的行末标识保持可见，交由 Daymark 校验。
- 完整事项的系统剪贴板文本仍包含 ID，所以可以跨文件移动并保留关联。将它粘贴到未配置保护的目录或其他软件中，ID 可能显示。
- ID 保留不依赖本次会话、一次性剪切凭证或源文件读取；只要剪贴板中原 ID 完整，插件重启后粘贴也不更换它。整行粘贴定位优先使用剪贴板中的行标记；只有纯文本时按当前选区粘贴，请在空行插入多行事项。
- 各文件的撤销历史相互独立。撤销源剪切会恢复原 ID，再次粘贴仍使用它，可能产生重复，交由 Daymark 同步校验，不自动改号。
- 多光标的事项剪贴板操作暂不支持。跨行选区如果只选中某个事项的部分隐藏身份，复制或剪切会拒绝执行并提示重新选完整行，不会静默丢弃中间事项的 ID。跨行替换也受到身份保护。行末 Delete 不用于合并两个事项，避免把 ID 放到正文中间。
- 含身份的整行文字拖拽会被阻止，请改用剪切／粘贴。原生复制行和同文件粘贴也保留 ID，插件不再因身份重复而阻止操作，Daymark 在同步时统一校验。
- 插件通过编辑器事务保护普通编辑，其他软件直接写文件、其他插件绕过事务过滤的改写不受此保护。插件不在保存后猜测并补回身份，也不直接写笔记文件。
- 0.2.1 在事务层纠正可确定的单次换行，并拒绝将保留的 ID 与保留正文分到不同行的模糊操作；跨行粘贴不会被当作回车。宿主插入的单次软换行也沿用安全分条规则，因为 Daymark 的事项正文按单行解析。已经在旧版中发生的 ID 错位不会自动猜测修复，需要撤销原操作，或依据原记录确认 ID 后恢复；切勿给原事项随意换新 ID。

## 开发与验证

开发环境：本工作区使用 Node.js 24.14.0。Obsidian 最低版本声明为 1.6.0，构建使用官方 SDK 1.14.4 的类型与其匹配的 CodeMirror 依赖；尚未在各 Obsidian 版本中完成运行矩阵验证。

```powershell
cd D:\Workspace\Temp\Daymark\plugins\daymark-id-guard
npm ci
npm run check
```

构建沿用官方示例的 TypeScript + esbuild + CommonJS 方式，`obsidian` 和 CodeMirror 保持 external，使用宿主提供的实例。输出 `main.js`，并生成仅含两个安装文件的 `release/daymark-id-guard/`。这些构建产物和依赖不提交 Git。修改的是独立 Obsidian 插件，不需要重建 Daymark 的 Flutter Windows 程序。

79 项插件测试使用真实 CodeMirror 状态、视图、命令及历史，在 jsdom 中运行；宿主生命周期测试模拟 Obsidian API。包括真实 `keydown` 事件、宿主优先处理回车、整行替换、事务元数据、禁用后的原始源码，以及原有的隐藏 DOM、编辑拦截、输入法事务、回车及子事项归属、缩进、只读、多行正反向选区、最后一条隐藏 ID、跨文件剪切和复制、重复及同文件粘贴、重建剪贴板处理器、撤销源剪切、剪贴板写入失败、目录切换与设置写入失败。Daymark 的回归测试另外覆盖兼容 ID 的父子树合并、字段差异、父身份比较、标签继承、来源删除与恢复、原子失败、完成日期及时间不重复计数。

**尚未在真实 Obsidian／Tasks 插件组合及原生中文输入法中运行验证。** 安装到日常仓库前，建议先在隔离仓库完成：当前行输入与删除、中文组词确认、勾选完成、父子事项缩进、多行选择后跨文件剪切、复制、重复粘贴、撤销重做、源码模式与临时解锁。原生窗口测试须遵循仓库要求，使用私有非活动桌面，不能在活动桌面打开自动测试窗口。
