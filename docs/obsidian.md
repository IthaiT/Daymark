# Obsidian 事项与完整备份

在设置的「Obsidian 事项」中选择文件夹，例如 `E:\Data\Documents\Vault\Daymark`。点击「立即同步」导入当前内容，再点击「保存」记住目录；以后启动时自动同步。同步失败保留上次的事项和当前输入。只读取所选目录直属的 `.md` 文件，不跟随文件符号链接，不递归扫描整个仓库。

每个文件是一条大事项，标题为文件名。文件属性示例：

```yaml
---
parent: "[[另一事项]]"
tags:
  - 主业
  - 副业
---
```

不写 `parent`、留空或填写「最顶层事项」表示顶层。双链必须指向本次目录中的文件；支持双链别名和带仓库目录的双链。Obsidian 通常会在文件改名时更新双链，未更新的父链会阻止同步。`tags` 使用现有标签名称或完整路径，例如 `主业/研发`；缺失标签自动创建，重名且无法定位时要求使用完整路径。子事项继承全部父事项标签。

```markdown
- [ ] 方案调研 | 对比三种方案
    - [/] 等待确认 | | 已发出问题
    - [-] 取消方案
- [x] 完成验证 | 验证核心流程 | 测试通过
```

三个字段依次为名称、描述、结果，后两个可以省略或留空。缩进支持空格和制表符。正文中的竖线写为 `\|`；双链别名和行内代码里的竖线保留。代码块中的示例复选框不导入。

| Markdown | 事项页状态 | 记录名称候选 |
| --- | --- | --- |
| `[ ]` | 待办 | 显示 |
| `[/]` | 暂停 | 隐藏 |
| `[-]` | 已取消 | 隐藏 |
| `[x]` / `[X]` | 已完成 | 隐藏 |

事项行中任一字段的 `#标签` 会成为该事项自己的标签，并叠加父事项与文件属性中的标签；支持中文、多个标签和 `#父标签/子标签`，同一标签去重。双链中的标题锚点、行内代码及转义井号保留原样。

Tasks 官方格式中的优先级、日期、重复规则、完成后行为、依赖和任务标识会从三个显示字段中过滤；也支持相应的 Dataview 方括号或圆括号字段。原始行和完整文件内容仍保存在事项来源中。未知的复选框状态、缺失名称、重复 ID、无效 YAML 或父链循环会报错，保留现有数据。

## 稳定身份与单向同步

事项行末使用 Obsidian 原生块 ID，例如 `^daymark-obsidian-UUID`；文件级 ID 独占末尾一行，例如 `^daymark-file-obsidian-UUID`。旧 `<!-- daymark:... -->` 和文件注释会在同步时转换，原来的事项 ID 与记录关联保持不变。已经存在的用户块 ID 保留，由完整事项树保存它与历史 ID 的对应关系。改名、变更缩进或跨文件移动时，应移动完整的事项行；文件改名保留文件内容。

Obsidian 阅读模式会隐藏块 ID；实时预览仍可能显示，所以提供 [隐藏样式](../tools/obsidian-daymark.css)。把文件复制到仓库 `.obsidian/snippets/`，然后在 Obsidian「设置 → 外观 → CSS 代码片段」刷新并启用。它仅在实时预览中让 `.cm-blockid` 透明，源码模式仍可检查；所有原生块 ID 都受此样式影响。CSS 不改 Markdown、剪贴板或编辑命令，也不需要安装插件。 **此样式不保护 ID，编辑时仍可破坏它。** 无插件时建议改用[编辑行显示 ID 的样式](../tools/obsidian-daymark-reveal-on-edit.css)，减少盲改；需要始终隐藏并防误删时，参见[编辑保护调研](obsidian-id-protection.md)。

**剪切请使用整行或完整子树。** 无选区时将光标放在事项行，按 Ctrl+X，编辑器会剪切整行源码，包括不可见的行尾 ID；跨文件粘贴后 ID 不变。仅选择名称或一部分正文再剪切属于文本编辑，不能保证携带行尾 ID。复制建立独立事项时，应在源码模式移除副本 ID；重复 ID 会阻止同步，避免错误关联。文件 ID 不要与单条事项一起移动。CSS 隐藏不等于不可删除，整行操作的说明不能代替当前 Obsidian 版本及其他插件组合下的实测。

同步会保存需要更改的原始文件到数据目录 `obsidian-originals/*.json`，检查源内容是否已发生变化，再原子写入。除身份标识外保留原内容。若只完成部分文件写入，重试复用已有 ID；未闭合代码块或注释会阻止同步，以免新标识进入代码或注释中。

Markdown 是导入字段的来源，导入事项在 Daymark 事项页只读；请在 Obsidian 中修改后同步。本地新建事项继续支持原有编辑。源中删除的文件或事项不会从 Daymark 删除，而是标记「源中已移除，历史保留」，从记录候选隐藏。重新出现时按 ID 恢复。记录始终引用事项 ID，原有标题、备注、时间和记录标签不随同步重写。

名称列仅搜索待办事项，按完整匹配、前缀、中间文字依次排序，不推荐标签。不匹配时可直接输入自由名称，并在标签列手动选择标签；仍允许未分类记录。选择事项自动补全继承标签，保留手动选择的标签。记录表将所属事项显示为深灰白字标签，与其他标签使用相同的圆角、字号和间距，仅以颜色区分，不显示前缀；窄列优先保留所属事项并截断长名称。记录表为每个标签单独显示颜色；宽度不足时以「+数量」菜单显示剩余标签，行高保持不变。标签列支持多个标签，重复选择某一标签会移除它，「未归类」清空记录标签并保留已关联事项。

事项页左上角的同步图标直接刷新已配置目录。详情页不显示删除按钮或来源提示小字；空描述和空结果保持留白，实际正文保留。标签使用独立的纯文字色块。来源事项右上角可在 Obsidian 中打开并定位到对应事项块，时间记录的右键菜单也提供此操作。名称、描述、结果及时间记录标题中的 `[[双链]]` 可点击；支持别名、标题和块锚点，通过官方 `obsidian://open?path=...` 协议打开。无目录的短文件名先在事项目录查找，带目录链接可在具有 `.obsidian` 的仓库根目录定位；不递归扫描个人仓库。

## 完整事项树备份

应用保持 `items.json` 版本 1；新增的可选 `source` 包含目录、文件名、源类型、原始文本、顺序和是否已移除。旧事项无需迁移。原来的事件 CSV 前六列和 UTF-8 BOM 保留，沿用当前分支已有的第七列 `item_id`；多个标签继续写在带 CSV 引号保护的 `tag_id` 字段中。

应用启动、成功修改数据、跨日和正常关闭时，在数据目录内维护：

| 文件 | 内容与保留方式 |
| --- | --- |
| `tree-backups/latest.json` | 当前完整事项树、标签和全部已保存记录，覆盖更新 |
| `tree-backups/yesterday.json` | 上一个有快照日期的最终版本，跨日覆盖一次 |
| `tree-backups/monthly/YYYY-MM-01.json` | 每月 1 日首次成功快照，长期保留且不覆盖 |

所有状态及事项属性、层级、记录关联、原始 Markdown 均包含在快照中，未保存草稿不进入备份。快照记录真实日期；若某日没有运行软件，无法补造当天状态，「昨日」文件实际保存最近一次有快照的日期，也不会补造错过的月初。月初首次快照代表当天开始使用时的状态。

快照与工作数据都使用同目录原子替换。备份失败时，当前数据保存会回滚并报告失败；损坏快照保留原文件，不静默覆盖。`archive.json` 仍独立负责完成日期的归档，与完整事项树备份各自保留。备份是重构核心数据的独立 JSON，包含完整源文件的节点可用于重建 Markdown。复制或人工恢复整个数据目录前，应先关闭 Daymark。

格式依据：[Tasks Emoji Format](https://github.com/obsidian-tasks-group/obsidian-tasks/blob/main/docs/Reference/Task%20Formats/Tasks%20Emoji%20Format.md)、[Dataview Format](https://github.com/obsidian-tasks-group/obsidian-tasks/blob/main/docs/Reference/Task%20Formats/Dataview%20Format.md)。

隐藏与剪切方案参考：[Obsidian 原生块引用](https://help.obsidian.md/links#Link+to+a+block+in+a+note)、[官方论坛 Hide block IDs](https://forum.obsidian.md/t/hide-block-ids/81063)、[CodeMirror 剪贴板实现](https://github.com/codemirror/view/blob/main/src/input.ts)、[Obsidian URI](https://help.obsidian.md/uri)。原生块 ID 可直接作为链接目标，普通 HTML/`%%` 注释在实时预览中不能单靠语法保证隐藏；仅按名称或内容散列推断身份也无法可靠处理改名和重名事项，因此选择原生块 ID 加显示样式。
