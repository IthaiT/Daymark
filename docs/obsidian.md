# Obsidian 事项与完整备份

在设置的「Obsidian 事项」中选择文件夹，例如 `E:\Data\Documents\Vault\Daymark`。点击「立即同步」导入当前内容，再点击「保存」记住目录；以后启动时自动同步。同步失败保留上次的事项和当前输入。只读取所选目录直属的 `.md` 文件，不跟随文件符号链接，不递归扫描整个仓库。

每个文件是一条大事项，标题为文件名。文件属性示例：

```yaml
---
parent: "[[另一事项]]"
tags:
  - 主业
  - 副业
daymark-id: "^daymark-obsidian-4bef7cb7-69ff-47e1-a77c-0da648622b75"
---
```

不写 `parent`、留空或填写「最顶层事项」表示顶层。双链必须指向本次目录中的文件；支持双链别名和带仓库目录的双链。Obsidian 通常会在文件改名时更新双链，未更新的父链会阻止同步。`tags` 使用现有标签名称或完整路径，例如 `主业/研发`；缺失标签自动创建，重名且无法定位时要求使用完整路径。子事项继承全部父事项标签。

```markdown
- [ ] 方案调研 | 对比三种方案
    - [/] 等待确认 | | 已发出问题
    - [-] 取消方案
- [x] 完成验证 | 验证核心流程 | 测试通过
```

三个字段依次为名称、描述、结果，后两个可以省略或留空。缩进支持空格和制表符。正文中的竖线写为 `\|`；双链别名和行内代码里的竖线保留。代码块中的示例复选框不导入。

| Markdown | 事项页状态 | 记录名称候选 |
| --- | --- | --- |
| `[ ]` | 待办 | 显示 |
| `[/]` | 暂停 | 隐藏 |
| `[-]` | 已取消 | 隐藏 |
| `[x]` / `[X]` | 已完成 | 完成日期在最近 7 个自然日内显示 |

事项行中任一字段的 `#标签` 会成为该事项自己的标签，并叠加父事项与文件属性中的标签；支持中文、多个标签和 `#父标签/子标签`，同一标签去重。双链中的标题锚点、行内代码及转义井号保留原样。

Tasks 官方格式中的优先级、日期、重复规则、完成后行为、依赖和任务标识会从三个显示字段中过滤；也支持相应的 Dataview 方括号或圆括号字段。原始行和完整文件内容仍保存在事项来源中。未知的复选框状态、缺失名称、重复 ID、无效 YAML 或父链循环会报错，保留现有数据。

Daymark 自行跟踪完成状态，不要求安装 Tasks 插件。同步时，已有事项从未完成变为完成，记录本次首次发现完成的日期；重复同步、改名和移动不会刷新日期。最近 7 个自然日按本机日期计算，包括今天及前 6 天，未来日期不参与。第一次导入时就已完成且没有日期的事项不会被当成新完成事项。重新打开为待办后清空本轮完成日期，始终可搜索，再次完成时重新计时；既有记录和 ID 保持不变。Daymark 关闭期间只能观察下次同步的状态，无法还原真实勾选时间，也无法看到两次同步之间已完成又重新打开的过程。

笔记已有 `✅ YYYY-MM-DD`、`[completion:: YYYY-MM-DD]` 或 `(completion:: YYYY-MM-DD)` 时，可以作为可选完成日期导入，覆盖本地观察日期；代码、双链、注释中的示例不算。仅完成状态读取日期，待办行残留的日期不生效。没有插件或日期也可使用本地状态跟踪，Daymark 不会为此向 Markdown 追加日期。完成日期存为事项可选字段 `completed_on`，包含在完整树备份中；超过搜索期限不会删除事项或时间记录。

## 稳定身份与单向同步

所有 Obsidian 事项统一使用完整的 `^daymark-obsidian-UUID` 身份值，UUID 使用小写十六进制。文件仍代表大事项，正文复选框代表子事项。笔记把这个完整值保存在 YAML 的 `daymark-id` 属性中，正文事项把同一个完整值写在行末；内部事项树和时间记录的 `item_id` 也直接保存这个值，不裁剪前缀、不编码、不另建别名。缺失或空白 ID 在同步时自动生成。

合并文件时，在目标文件创建 `- [ ] 跳槽`，把原笔记 `daymark-id` 的值原样粘贴到行末，再把原正文作为它的子事项移动过去。反向拆成独立文件时，把该行末 ID 原样放入新笔记属性。两种位置表示同一个事项，完整子树的 ID 和时间记录关联保持不变。也可保留多个出现位置，但各处父事项和解析字段必须一致；例如保留原笔记时，其 `parent` 须指向目标文件，笔记文件名须与内联事项名称一致，自身标签也须一致。

只接受这一种身份格式。旧注释、旧文件块标识、缺少前缀的属性、自定义事项块 ID 和编码 ID 都会报错，不做自动迁移或历史别名匹配。已保存的 Obsidian 事项 ID 也必须符合完整格式；旧存储身份会阻止同步，不会悄悄生成第二个事项或改绑记录。

**相同 ID 可以出现在多个位置。** 同步先解析全部位置并解析父链，再比较父事项 ID、名称、描述、结果、状态、显式完成日期和自身标签。全部一致时只保存一个逻辑节点，各处子事项按各自 ID 汇总到这个节点下，可继续递归合并；文件位置、行号、缩进、子事项列表及现有解析器忽略的 Tasks 元数据不用于判定身份冲突。标签按现有 Unicode casefold 规则比较集合，顺序和重复不影响一致性；完整标签路径与短名称不擅自判定相等。

父事项按 **ID** 比较，不按名称猜测。笔记文件本身也是父事项，因此将同一条目复制到不同文件的顶层，即使正文相同，只要两份文件父 ID 不同，仍会冲突。多处共同引用同一逻辑父事项时，各处不同的子事项则正常汇总。不同 ID 即使名称相同也不会被合并。

兼容条目保留现有 JSON 版本和单一代表来源：优先选择文件事项，其次按既有来源路径和行序稳定选择，供「在 Obsidian 中打开」和界面排序使用；不依赖文件读取先后顺序。所有文件仍参与每次解析。删除某一个出现位置后，其余位置可继续提供同一节点；仅在最后一个位置消失后才按既有时间记录引用规则清理或保留「源已删除」。编辑一个位置后，需要同步修改其他位置的解析字段，Daymark 不自动回写副本。

只有同 ID 的父事项或解析字段不一致才报错，格式错误也继续报错；本次同步原子停止，源文件与已保存数据保持原样。冲突详情按组列出全部相关事项的名称、文件名、原始行号，以及不一致的字段和值；笔记身份会标出 `daymark-id` 属性位置。事项页同步、设置中的立即同步和启动自动同步均显示可滚动、可复制的详情窗口。请按文件名和行号定位，而不必查找被插件隐藏的 ID。

需要编辑时始终隐藏并防误改，可安装 [Daymark 事项保护插件](../plugins/daymark-id-guard/README.md)。配置与同步目录对应的仓库内相对路径后，实时预览和源码模式都会隐藏有效的事项行末 ID，并拦截普通编辑对它的破坏。0.2.0 使用标准的整行／多行剪切、复制和粘贴，均保留原 ID，不再提供子树专用命令，也不自动给复制内容改号；Daymark 在同步时合并兼容的同 ID 条目，只报告真正冲突。另有临时解锁命令。它不保护笔记 YAML 属性；当前已完成无窗口 CodeMirror 与宿主模拟测试，尚未在真实 Obsidian／Tasks 组合中运行验证。安装后请停用旧隐藏样式，以免解锁时 ID 仍被 CSS 隐藏。

不使用插件时，仍提供 [隐藏样式](../tools/obsidian-daymark.css)。复制到仓库 `.obsidian/snippets/`，在 Obsidian「设置 → 外观 → CSS 代码片段」启用。它仅在实时预览中让所有 `.cm-blockid` 透明，源码模式仍可检查，**不保护 ID**。也可选用[编辑行显示 ID 的样式](../tools/obsidian-daymark-reveal-on-edit.css)，减少盲改；设计依据和限制见[编辑保护调研](obsidian-id-protection.md)。

**剪切和复制多个事项请选择完整行。** 从第一行行首（含缩进与列表符号）选到最后一行的可见行末，Ctrl+X / Ctrl+C 后再到目标文件 Ctrl+V。保护插件会包含最后一条不可见的行末 ID，其他完整行的 ID 也原样保留。无选区时剪切／复制当前整行。重复粘贴、插件重启或撤销源剪切都不改号；只要同 ID 的父事项和解析字段一致，多个位置可长期保留，各处子事项汇总。复制后删除原处也可作为搬移；若希望建立独立事项，需临时解锁并移除副本 ID，再同步生成新身份。仅选择名称仍属于文本编辑，不能保证携带行尾 ID。笔记改名时保留 `daymark-id`；将文件事项合并为正文事项时，先临时解锁，再按上述规则转移完整 ID。整行操作的说明和自动化测试不能代替当前 Obsidian 及其他插件组合下的实测。

同步会保存需要更改的原始文件到数据目录 `obsidian-originals/*.json`，检查源内容是否已发生变化，再原子写入。除身份标识外保留原内容。若只完成部分文件写入，重试复用已有 ID；未闭合代码块或注释会阻止同步，以免新标识进入代码或注释中。

Markdown 是导入字段的来源，导入事项在 Daymark 事项页只读；请在 Obsidian 中修改后同步。本地新建事项继续支持原有编辑。源中删除的文件或事项会在下次成功同步时从 Daymark 删除，不会改成「已取消」。只有仍被已保存时间记录直接引用的事项会保留，显示「源已删除」并从记录候选隐藏；应用显示引用数量，可点击「查看事项」定位。没有记录引用的父级和其他子事项照常删除，保留节点及本地子事项上移至最近的保留父级，同时保留原先继承的标签。调整或删除最后一条时间记录引用后，再次同步即可清理保留节点。携带 ID 跨文件移动或合并时，按当前目录全部文件匹配，不会误删或提示；同 ID 重新出现时恢复同步。记录始终引用事项 ID，原有标题、备注、时间和记录标签不随同步重写。

名称列搜索待办与近期完成事项，支持名称中间文字及完整父级路径，不推荐标签。匹配一个父事项时，其符合状态条件的子孙事项也按树顺序显示；精确匹配、前缀、中间文字及完整路径依次决定子树排序，父级自身不可记录也不妨碍查找其可记录的子事项。候选不再截断为前 8 条，长列表滚动显示，方向键会滚动到选中行。候选前不显示图标，有限缩进表达层级，名称和父级路径各占一行，过长省略并支持悬停查看全文；近期完成项显示「已完成」。不匹配时可直接输入自由名称，并在标签列手动选择标签；仍允许未分类记录。选择事项自动补全继承标签，保留手动选择的标签。记录表将所属事项显示为深灰白字标签，与其他标签使用相同的圆角、字号和间距，仅以颜色区分，不显示前缀；窄列优先保留所属事项并截断长名称。记录表为每个标签单独显示颜色；宽度不足时以「+数量」菜单显示剩余标签，行高保持不变。标签列支持多个标签，重复选择某一标签会移除它，「未归类」清空记录标签并保留已关联事项。

事项页左上角的同步图标直接刷新已配置目录。详情页不显示删除按钮或来源提示小字；空描述和空结果保持留白，实际正文保留。标签使用独立的纯文字色块。来源事项右上角可在 Obsidian 中打开并定位到对应事项块，时间记录的右键菜单也提供此操作。名称、描述、结果及时间记录标题中的 `[[双链]]` 可点击；支持别名、标题和块锚点，通过官方 `obsidian://open?path=...` 协议打开。优先打开事项目录中已存在的精确文件；其他双链通过具有 `.obsidian` 的仓库根目录交给 Obsidian 原生解析，短文件名可指向仓库任意子目录中的笔记，不会仅因文件不在事项目录或仓库根目录而误报不存在。此过程不递归扫描个人仓库；找不到目标时由 Obsidian 提示。协议的 `path` 用来确定仓库，仓库内剩余路径按 `file` 参数解析，详见 [Obsidian 官方协议说明](https://help.obsidian.md/uri#Open%20note)。

## 完整事项树备份

应用保持 `items.json` 版本 1；新增的可选 `source` 包含目录、文件名、源类型、原始文本、顺序和是否已移除。旧事项无需迁移。原来的事件 CSV 前六列和 UTF-8 BOM 保留，沿用当前分支已有的第七列 `item_id`；多个标签继续写在带 CSV 引号保护的 `tag_id` 字段中。

应用启动、成功修改数据、跨日和正常关闭时，在数据目录内维护：

| 文件 | 内容与保留方式 |
| --- | --- |
| `tree-backups/latest.json` | 当前完整事项树、标签和全部已保存记录，覆盖更新 |
| `tree-backups/yesterday.json` | 上一个有快照日期的最终版本，跨日覆盖一次 |
| `tree-backups/monthly/YYYY-MM-01.json` | 每月 1 日首次成功快照，长期保留且不覆盖 |

所有状态及事项属性、层级、记录关联、原始 Markdown 均包含在快照中，未保存草稿不进入备份。快照记录真实日期；若某日没有运行软件，无法补造当天状态，「昨日」文件实际保存最近一次有快照的日期，也不会补造错过的月初。月初首次快照代表当天开始使用时的状态。

快照与工作数据都使用同目录原子替换。备份失败时，当前数据保存会回滚并报告失败；损坏快照保留原文件，不静默覆盖。`archive.json` 仍独立负责完成日期的归档，与完整事项树备份各自保留。备份是重构核心数据的独立 JSON，包含完整源文件的节点可用于重建 Markdown。复制或人工恢复整个数据目录前，应先关闭 Daymark。

格式依据：[Tasks Emoji Format](https://github.com/obsidian-tasks-group/obsidian-tasks/blob/main/docs/Reference/Task%20Formats/Tasks%20Emoji%20Format.md)、[Dataview Format](https://github.com/obsidian-tasks-group/obsidian-tasks/blob/main/docs/Reference/Task%20Formats/Dataview%20Format.md)。

隐藏与剪切方案参考：[Obsidian 原生块引用](https://help.obsidian.md/links#Link+to+a+block+in+a+note)、[官方论坛 Hide block IDs](https://forum.obsidian.md/t/hide-block-ids/81063)、[CodeMirror 剪贴板实现](https://github.com/codemirror/view/blob/main/src/input.ts)、[Obsidian URI](https://help.obsidian.md/uri)。原生块 ID 可直接作为链接目标，普通 HTML/`%%` 注释在实时预览中不能单靠语法保证隐藏；仅按名称或内容散列推断身份也无法可靠处理改名和重名事项，因此保留原生块 ID，并提供编辑保护插件和可选显示样式。
